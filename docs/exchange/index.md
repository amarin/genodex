# Обмен данными между экземплярами

> **Статус: обсуждение, не реализовано.** Раздел фиксирует итоги обсуждения
> от 2026-09-23. Решения здесь — направление, а не принятый дизайн; перед
> реализацией каждого пункта нужен отдельный проход обсуждения (см. раздел F в
> [todo.md](../todo.md)). Полнота требований проверяется по карте
> [requirements.md](requirements.md). Транспорт и поиск узлов вынесены в
> отдельный документ — [peer-discovery.md](../peer-discovery.md).

## Проблема

Два пользователя держат собственные экземпляры программы на своих компьютерах, с
собственными базами. Их данные пересекаются: одни и те же персоны, семьи,
населённые пункты, одни и те же архивные дела. Нужен механизм, который позволит
одному обогатить свою базу данными другого, не теряя контроля над своей.

## Главный принцип

> Цель обмена — **не общая база**. Каждый пользователь остаётся единоличным
> владельцем своих данных. Обмен приносит чужие утверждения с указанием
> авторства, но ни одно из них не меняет локальные данные без решения владельца.

Расхождение баз — нормальное состояние, а не дефект. У пользователей разная
глубина проработки, разные выводы из одних и тех же документов и разная
ответственность за результат. Поэтому автоматическое слияние (CRDT, «последняя
запись побеждает», алгоритмическое разрешение конфликтов) здесь не применяется:
сводить нечего, есть два независимых мнения о реальности.

## Принятые в обсуждении решения

| № | Решение | Следствие | Блок |
|---|---|---|---|
| 1 | Чужие данные живут **в той же базе**, у каждой сущности и каждого факта есть привязка к источнику (моё / чужое, уровень доверия) | проще поиск и отображение; происхождение становится сквозным атрибутом модели | [provenance](provenance.md) |
| 2 | **Единица обмена — отдельный факт-поле**, не сущность целиком | дороже в реализации, но даёт приватность, сужение набора фактов и пофактовую достоверность | [wire-format](wire-format.md) |
| 3 | **Транзит разрешён**: всё полученное может быть передано дальше | приватность обеспечивается на отдаче: отдал — значит счёл непубличным только то, что не отдал | [privacy](privacy.md) |
| 4 | Принятое значение — **замороженная копия**, с возможностью подписаться на обновления по срезу интересов | база не меняется без участия владельца, но обновление не теряется из виду | [provenance](provenance.md), [subscriptions](subscriptions.md) |
| 5 | **Подписка непрозрачна для координатора**, если он сам не подписан на тот же топик | подписка возникает только между знакомыми узлами, поэтому топик солится их общим секретом | [subscriptions](subscriptions.md) |
| 6 | **Поиск партнёров — два разных канала**: открытый каталог тем (место, полк, учреждение) и слепые токены точек интереса (персона, семья) | публикация и поиск только вручную, роли разделены, по умолчанию только заведомо умершие | [discovery](discovery.md) |
| 7 | **`origin` — пользователь**, устройства подчинены идентичности; версия факта `(generation, device, seq)`; синхронизация своих устройств — отдельный механизм с автоприменением | вторая пишущая база (офлайн в архиве) возможна; конфликты идут во входящий ящик | [identity](identity.md) |
| 8 | **Доверие к партнёру — отдельная ось**: четыре состояния, вручную, привязано к автору факта | влияет только на подачу (порядок предложений, пороги сопоставления); не управляет отдачей, не включает автоприём, по сети не передаётся | [trust](trust.md) |
| 9 | **Происхождение — сайдкар, а не колонки в сущностях**: `fact_origin` плюс `foreign_claim`, адрес факта — пара (сущность, поле) | таблицы сущностей не меняются; словарь имён полей становится частью внешнего контракта | [provenance](provenance.md) |
| 10 | **Вложения — по отдельным правилам**: метаданные в потоке, файл по запросу, изображение фрагментом по `anchor.rect`; режим распространения отдельно от `private` | режим «не передавать» блокирует отдачу файла; скан разворота содержит посторонние семьи, поэтому кадрирование обязательно | [attachments](attachments.md) |
| 11 | **Первый работающий обмен — файловый**: подписанный контейнер, два режима экспорта, карточка контакта внутри | сетевая часть добавляет удобство, а не возможность; знакомство возможно без сети | [offline](offline.md) |
| 12 | **Формат — JSON Lines, пакет — цепочка хешей; две подписи**: на каждой записи авторство, на пакете доставка | подписываются переданные байты, канонизация не нужна; запись неизменяема, поэтому подмножество пересылается без потери авторства | [wire-format](wire-format.md) |
| 13 | **Одна лестница раскрытия для веба и обмена**: `Access` из трёх уровней, правила вычисляют уровень факта, флаг — исключение | «жив» определяется в том числе по позднему документальному упоминанию, иначе персоны без дат все считались бы живыми | [privacy](privacy.md) |
| 14 | **Входящий ящик: лента производная, отклонение по версии** | лента перестраивается из предметных таблиц; исправленный партнёром факт приходит заново, а повторная доставка отклонённого — нет | [inbox](inbox.md) |
| 15 | **Контроль потоков локален**: трёхступенчатая блокировка, честный ответ вместо молчания, журнал отданного по адресам фактов | блокировка не возвращает отданное; журнал показывает, кому писать при отзыве | [control](control.md) |
| 16 | **Группа — локальная выборка партнёров**, без сетевой семантики | партнёры о группах не знают; для доставки данных группа не нужна — хватает транзита с подписями | [groups](groups.md) |
| 17 | **Агент читает и готовит, наружу не действует**: содержимое чужих фактов — данные, а не инструкции | инструментов отдачи и доверия в MCP нет физически; предпросмотр отдачи — вторая линия | [agent](agent.md) |
| 18 | **Никакого молчаливого отбрасывания**: всё неприменённое журналируется с причиной; очистка зеркала — массовое отклонение | пользователь всегда отличает отказ от поломки; эталонные контейнеры делают совместимость версий проверяемой | [operations](operations.md) |
| 19 | **Сопоставление — правила с доводами, а не оценка числом**; автосвязывание только там, где есть строгий идентификатор | архивные дела по шифру и населённые пункты по пути до волости; персоны — никогда | [matching](matching.md) |
| 20 | **Один язык среза на подписки, группы и экспорт**: якорь, правило расширения, фильтры | по сети едет идентификатор шаблона и параметры, а не код: подписка не должна исполнять чужой код на моей машине | [subscriptions](subscriptions.md) |
| 21 | **Отзыв подписан автором и расходится сам**: по подпискам и адресно по журналу отданного, дальше по цепочке автоматически | чужой факт отозвать нельзя; удаление сущности не каскадит, принятые факты остаются моими | [revocation](revocation.md) |
| 22 | **Транспорт за интерфейсом, выбор отложен**: stdlib по умолчанию, libp2p как запасной; параметры эпох — сетевые константы | решение о NAT-стеке принимается на этапе M2 и заменяется локально; координатор живёт на приоритетах и бюджете трафика, без оплат | [peer-discovery](../peer-discovery.md) |

Вынесены в отдельные обсуждения и в этом документе не раскрываются: принципы
сопоставления сущностей ([matching](matching.md)) и правила приватности
([privacy](privacy.md)).

## Модель в двух словах

**Три категории данных в одной базе:**

| Категория | Владелец | Изменяется | Видно пользователю как |
|---|---|---|---|
| собственные факты | я | мной | мои данные |
| чужие факты (зеркало) | узел-источник | только обновлением от источника | «данные партнёра B» рядом с моими |
| связи тождества | я | мной | «его Иван = мой Иван», обратимо |

**Происхождение факта** неизменно: факт, созданный у B, навсегда остаётся фактом
B, через сколько бы рук он ни прошёл. Это гасит размножение копий и петли
`A → B → C → A`. Подробности — [provenance](provenance.md).

**Доказательная база важнее того, кто её принёс.** Вместе с утверждением
передаётся его доказательство: ссылка на фонд, опись, дело и лист ценна сама по
себе, даже если выводы разойдутся. Поэтому факт с доказательством сохраняет свою
цепочку `Source → Citation → SourceLink`, а партнёр остаётся в происхождении как
путь доставки. Источником вида «сообщено исследователем U» партнёр становится
только для утверждений, пришедших без доказательств — см. [trust.md](trust.md#партнёр-как-источник-важное-разграничение).
Существующий принцип модели («доказательства привязаны к утверждениям, каждое со
своей достоверностью», см. [data-model.md](../data-model.md)) работает без изменений.

## Конвейер

```
подписка или разовый запрос по срезу интересов
   → партнёр отдаёт факты, прошедшие фильтр приватности (полные или сокращённые)
   → входящий ящик предложений (база не меняется)
   → решение человека: зеркало / принять факт / связать сущности
   → факт в моей базе с происхождением и SourceLink на узел-источник
   → источник изменил или отозвал факт → уведомление, снова во входящий ящик
```

Автоматического применения нет ни на одном шаге. Кнопки «принять всё» быть не
должно: она превращает проработанную базу в свалку за один клик, а откат
практически невозможен.

## Что добавляется в схему

Ориентировочно, для оценки объёма. Собственные таблицы сущностей при этом
не меняются — модель обмена надстраивается над моделью данных, а не переписывает
её:

- `remote_nodes` — исследователи: идентичность, отображаемое имя, уровень доверия,
  состояние подписок, курсоры;
- `fact_origin` — сайдкар происхождения моих фактов, ключ — адрес (сущность, поле);
- `foreign_claim` — чужие утверждения, ещё не принятые (зеркало), значение в
  формате обмена;
- `links` — связи тождества, включая отрицательные («это НЕ тот же человек»);
- `inbox` — необработанные предложения;
- `change_log` — журнал изменений: дельты, `based_on`, отмена пакетом (общий с E4);
- `outbound_log` — журнал отданного: кому, когда, какие адреса фактов и версии;
- кэш чужих вложений и его консоль: происхождение файла, связи, размер, очистка;
- новый вид `Source` — «сообщено исследователем U» (только для утверждений без доказательств);
- уровень доверия при карточке исследователя ([trust](trust.md)).

## Зависимости от других разделов

- **Транспорт.** Соединение по идентичности, взаимное согласие, проход через NAT
  и координаторы — [peer-discovery.md](../peer-discovery.md). Обмен данными
  начинается там, где тот документ заканчивается: есть установленное
  аутентифицированное соединение между двумя доверенными узлами.
- **Контракты людей и событий** (раздел C в [todo.md](../todo.md)). Их стоит
  проектировать уже с учётом происхождения факта, иначе переделка.
- **`origin` и пакеты изменений** из раздела автоматизации ввода
  ([ux/assisted-entry.md](../ux/assisted-entry.md#журнал-пакетов-изменений-и-отмена),
  задача E4). Там происхождение вводится для отмены пакетом, здесь — для обмена.
  **Это должна быть одна модель**, а не две; согласовать до реализации любой из них.
- **Auth/Access** ([data-model/auth.md](../data-model/auth.md)). Узел-партнёр —
  не владелец и не совладелец; ему нужен собственный режим доступа, отдельный от
  публичного и полного.

## Что вне раздела

- Прикладной протокол соединения и поиск узлов — [peer-discovery.md](../peer-discovery.md).
- Импорт и экспорт GEDCOM и других внешних форматов: смежно, но это обмен с
  программами, а не с узлами, и там нет ни происхождения, ни подписок.
- Совместная работа нескольких человек над одной базой — это совладельцы из
  [auth.md](../data-model/auth.md), другая задача.
