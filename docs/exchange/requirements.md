## Как пользоваться

Требования сгруппированы по стадиям жизненного цикла: от идентичности узла до
эксплуатации. У каждого — статус:

| Статус | Значение |
|---|---|
| **решено** | направление зафиксировано в обсуждении, детали в блоке раздела |
| **частично** | обсуждалось, но требование не доведено до проверяемой формулировки |
| **дыра** | не обсуждалось вовсе; описание — в разделе [Дыры](#дыры-h1h12). **На 2026-09-23 таких строк не осталось** |

Закрытое обсуждение меняет статус и уточняет формулировку требования. Новые
требования дописываются в свою стадию.

`origin` — пользователь, ключи устройств подчинены идентичности; версия факта
`(generation, device, seq)` с ростом `generation` при восстановлении из копии и
самопочинкой при соединении; второе устройство заводится регистрацией, в поездку
едет вся база без ключа идентичности; восстановление — резервная копия плюс
разделение секрета 3 из 5; компрометация отсекается по `received_at` получателя.

### H2. Слияние и удаление собственных сущностей

**Закрыта.** Обсуждена 2026-09-23 вместе с H1. Итог — [identity.md](identity.md#слияние-разделение-и-алгебра-операций):
ID не переиспользуется, слияние и разделение передаются как данные с версией,
ведётся история идентичности сущности; зеркало применяет их автоматически, а
связи тождества помечаются «требует проверки». Разделение сущности спроектировано
наравне со слиянием.

### H3. Модель доверия к партнёру

**Закрыта.** Обсуждена 2026-09-23 (задача F13). Итог — [trust.md](trust.md): доверие к
качеству исследования — отдельная ось от `Reliability`, четыре состояния,
ставится вручную, привязано к автору факта, влияет только на подачу (порядок
предложений, пороги сопоставления, подсветку расхождений) и никогда — на отдачу
или автоматическое принятие. По сети не передаётся, поэтому **репутации в сети
нет** — это предопределяет часть ответа в [H6](#h6-недобросовестный-партнёр).
Попутно закрыт отказом пункт о группах партнёров в [privacy](privacy.md#разные-правила-для-разных-партнёров).

### H4. Вложения, сканы и их правовой статус

**Закрыта.** Обсуждена 2026-09-23 (задача F15). Итог — [attachments.md](attachments.md):
вложения не идут в общем потоке (метаданные в дельтах, файл по запросу);
изображение передаётся фрагментом по `anchor.rect` — это и объём, и право, и
приватность, потому что скан разворота содержит записи о посторонних семьях;
режим распространения — отдельная ось от `private`, по умолчанию строжайший, и
режим «не передавать» блокирует отдачу файла полностью. Технической защиты нет и
не заявляется. Полученные файлы кэшируются, кэшем управляют через отдельную
консоль. Правовая сверка объединена с F2a.

### H5. Офлайн-обмен файлом

**Закрыта.** Половина снята в F12 (синхронизация своих устройств тем же
форматом без сети), вторая половина обсуждена 2026-09-23 в задаче F14. Итог —
[offline.md](offline.md): подписанный zip-контейнер, два режима экспорта (для
партнёра с шифрованием и открытый срез со строгим порогом приватности), полный
срез вместо дельт (лишнее отбрасывает получатель по версиям), карточка контакта
внутри контейнера — знакомство возможно без сети. Принято требованием: **первый
работающий обмен в проекте — файловый**.

### H6. Недобросовестный партнёр

**Закрыта.** Обсуждена 2026-09-23 (задача F16). Итог — [control.md](control.md):
трёхступенчатая блокировка (подписка, данные, соединение), зеркало
заблокированного сохраняется, узел честно отвечает «обмен приостановлен» вместо
молчания, незапрошенный поток ограничивается жёстче запрошенного. Вопрос
репутации был закрыт раньше в [H3](#h3-модель-доверия-к-партнёру): её нет.
Попутно найдена и закрыта накрутка версий — повторное предложение создаётся
только при изменении содержимого.

### H7. Групповой обмен

**Закрыта.** Обсуждена 2026-09-23 (задача F17). Итог — [groups.md](groups.md):
группа — **локальная сохранённая выборка партнёров**, сетевой семантики нет,
партнёры о ней не знают, согласовывать нечего. Групп может быть много
(по общему предку, по точке интереса, по региону), выборка статическая или
динамическая. Для распространения данных группа не нужна вовсе: транзит плюс
подпись на каждой записи уже доставляют данные по кругу. Разделяемый объект с
консенсусом по членству отвергнут как несоразмерный. Массовые действия отложены.

### H8. Обмен в MCP-контуре

**Закрыта.** Первая половина — в F4 (агент читает ящик, решения за человеком),
вторая — 2026-09-23 в задаче F18. Итог — [agent.md](agent.md): агент делает всё,
что не покидает базу и не создаёт обязательств; отдача, публикация точек
интереса и установление доверия — только человек. Вторым, более сильным доводом
записана защита от инъекций: **содержимое чужих фактов — данные, а не
инструкции**, и инструментов отдачи в контракте MCP нет физически, а не отключены
настройкой.

### H9. Аудит отданного

**Закрыта.** Обсуждена 2026-09-23 (задача F19). Итог —
[control.md](control.md#журнал-отданного): журнал хранит партнёра, режим, время,
хеш контейнера, адреса фактов и версии; содержимое не дублируется, а
восстанавливается из `change_log`. Хранится бессрочно. Служит не отчётностью, а
инструментом: показывает, кому уже ушёл факт, который позже пометили приватным, и
позволяет ответить живому человеку на просьбу об удалении сведений о нём.

### H10. Расхождение часов

**Закрыта.** Обсуждена 2026-09-23 (задача F20). Итог —
[operations.md](operations.md#часы): перекрытие эпох на соседние, допуск по
коротким срокам, измерение расхождения при соединении с предупреждением
пользователю, решения только по локальному времени, записи «из будущего» — с
пометкой, всё время в UTC.

### H11. Ретеншн зеркала и объёмы

**Закрыта.** Обсуждена 2026-09-23 (задача F21). Итог —
[operations.md](operations.md#ретеншн-зеркала): очистка зеркала — это массовое
отклонение с выбрасыванием значения, автоматики по умолчанию нет, горизонт
журнала определяется самым отставшим активным подписчиком, tombstone живёт не
меньше горизонта. Заданы количественные ориентиры для проверки. Практическая
часть по файлам была закрыта раньше консолью кэша в [H4](#h4-вложения-сканы-и-их-правовой-статус).

### H12. Диагностика и тестирование

**Закрыта.** Обсуждена 2026-09-23 (задача F22). Итог —
[operations.md](operations.md#диагностика-для-пользователя): страница состояния
