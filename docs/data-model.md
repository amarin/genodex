# Модель данных genodex

> Живой документ: фиксирует модель данных сервиса (сущности и связи), согласованную
> на этапе проектирования. Дополнения обсуждаются и вносятся итеративно.
> Отправная точка — домен персональной генеалогии (см. `genealogy-router`);
> Obsidian-vault — один из вариантов хранилища, его структура и данные используются
> как подсказка и материал для тестирования, но НЕ являются источником истины.

## Принципы

1. **Одна реальная сущность — одна запись.** Связи между записями — по `id`.
2. **Доказательства привязаны к утверждениям.** Любой факт о сущности (атрибут персоны,
   событие, связь, проживание, принадлежность) может иметь `[0..n]` доказательств
   (`SourceLink`), каждое со своей достоверностью.
3. **Текст или ссылка.** Там, где элемент может быть либо текстом, либо ссылкой на
   сущность, используется универсальный тип `TextRef`: всегда есть читаемая строка,
   при ссылке добавляется `ref` — адрес перехода (страница в веб, файл в vault).
   Текст ссылки не обязан совпадать с названием цели (например, слово в другом падеже).
4. **Недоопределённость допустима.** Большинство полей опциональны. Персона может быть
   известна только по имени или даже только по полу (семейные воспоминания). Элемент
   списка может ссылаться на ещё не созданную сущность.
5. **Достоверность — градация на двух уровнях:** общая на `Source` и частная на
   `SourceLink` (скан достоверен для имён, но идентификация персоны — возможный
   однофамилец).
