# Принятые решения (log)

1. Единый `Event` + рёбра `Relation` (без отдельных сущностей брака/погребения).
2. Единая рекурсивная `AdministrativeDivision` (вместо типизированных
   Governorate/District/Volost).
3. `Source` — единая абстракция доказательства (скан+область / расшифровка / файл с
   тайм-кодом), `[0..n]` доказательств на утверждение. `Anchor` — интерфейс
   с реализациями `ArchiveAnchor`/`FileAnchor`/`URLAnchor`, а не один объект со всеми полями.
4. Родство — атомные рёбра; цепочки `F/M/D/S(P/A)` и наименования выводятся алгоритмом,
   а не хранятся.
5. Словари — отдельные сущности; элементы списков могут ссылаться на ещё не созданные
   сущности.
6. Универсальный тип `TextRef` («текст-или-ссылка») для элементов, которые могут быть
   и текстом, и ссылкой; у ссылки обязателен `type` цели (`type` + `ref` задаются вместе).
7. `Family` — отдельная сущность; члены могут быть недоопределёнными персонами
   (имя или даже только пол) без отдельной записи `Person`.
8. `FactDate` — структурированный Go-тип с методами сравнения (компоненты +
   `precision` + `modifier`), без парсинга строк при сравнении.
9. Поля имени в `PersonName` — `TextRef` с мягкой ссылкой на словари
   (`Surname`/`GivenName`/`Patronymic`); строка из источника сохраняется.
10. Поиск по словарям и адм. делению: жёсткие ссылки `type`+`id` > точное совпадение >
    совпадение по вариантам. Варианты написания — взаимосвязанные записи (`variants`).
11. Пол: `Person.gender` может быть неизвестен; вывод из имени/отчества разрешён только
    для не-нейтральных имён; в `GivenName.gender` признак обязателен (М/Ж/Н).
12. Родные/сводные братья и сёстры — сравнение цепочек от общего родителя
    (`MS`/`MD`/`FS`/`FD`); детальная проработка — отдельно при реализации вывода родства.
13. `AdministrativeDivision.type` — единый атрибут (уровень деления и вид нас. пункта
    в одном значении; уровень классифицируется по значению). `items` — хранимый список
    (не вычисляется из `parent_id`); `variants` — строки в сущности, без словаря на
    единицу; `renames []NamedPeriod` — переименования; `successors []TextRef` —
    преемственность систем деления (условное соответствие).
14. Архивная цепочка параметризована системой иерархии архива (аналогично системам
    адм. деления): `Archive.system`, рекурсивный узел `ArchiveNode` с типом из системы.
    Типизированные `Fund`/`Inventory`/`Case` заменяются узлами; последний уровень
    системы — единица учёта (дело/карточка/лист), глубина не зафиксирована.
15. `ArchiveDocument` — отдельная сущность под единицей учёта (дело — подшивка
    документов; дело из одного документа = единица + один документ). У документа свои
    заголовок, период и география; ровно один уровень вложенности — ниже только сканы.
16. Сканы страниц/листов — `Attachment` с `page`/`rect`; привязка к `ArchiveNode`
    (`node_id`, строгая), уточнение до документа (`document_id`).
17. Населённый пункт — уровень `AdministrativeDivision.type` (вид нас. пункта
    классифицируется по значению наряду с уровнем деления), отдельной сущности
    `settlement` нет.
18. Никаких полей с произвольной структурой: поля `Metadata map[string]string`
    удаляются из всех сущностей и моделей. Схема БД — полная колоночная
    (сущность = таблица, коллекция = связная таблица, value-тип = колонки/
    таблицы), JSON-блобов нигде нет.
19. Поиск конечный — отдельная таблица `search_index` с терминами,
    нормализованными в Go (`strings.ToLower`, корректно для кириллицы):
    канонический регистр хранится в колонках сущностей, индекс — производная
    копия; запрос — по lowered-подстроке (`LIKE`), без зависимости от
    sqlite-коллаций.
20. Несоответствия типов в алгоритмах исключаются номинальными типами:
    enum-домены (`SourceKind`, `EventType`, `PersonGender`, `RelationKind`,
    `AdminDivisionType`, `PersonNameType`, `Reliability`, `AttachmentKind`,
    `ArchiveNodeType`, `NameGender`, `Type`) и `ID` для всех id-полей и строгих
    ссылок. Полная номинальная типизация прочих атрибутов — отдельный будущий
    проход.
21. Цепочка доказательств — трёхуровневая `SourceLink` → `Citation` → `Source`:
    `Source` — библиографическая запись (`anchor` и `text` из решения 3 переезжают
    на цитату), `Citation` — переиспользуемый конкретный фрагмент (`anchor` +
    расшифровка `text`, строгая ссылка `source_id`), `SourceLink` ссылается на
    `citation_id`. Одна цитата — много утверждений; повторное цитирование через
    поиск существующей цитаты.
22. `Note` — отдельная сущность для произвольных текстов (заметка/статья/книга/глава)
    в markdown: `kind` + `parent_id` (иерархия «книга → главы»), `sources []SourceLink`.
    Не заменяет короткие `notes []TextRef` на сущностях; на Note можно сослаться
    через `TextRef`.
23. `Relation.kind` расширяется деятельными связями: `blood`/`marriage`/`adoption`/
    `associate`; при `kind=associate` задаётся `rel_type` (расширяемый список:
    сосед, коллега, крёстный, свидетель, друг,…). Цепочки родства и вывод
    наименований строятся только по первым трём видам.
24. Приватность — флаг `private` на primary-сущностях: Person, Relation, Family,
    Event, Residence, Note, Citation, Source, Repository, Archive, ArchiveNode,
    ArchiveDocument, Attachment. Словари, адм. деление, церкви и приходы флага
    не имеют.
25. `Repository` — отдельная сущность для учреждения-хранилища (архив/библиотека/
    музей/частный фонд): `name`, `type`, `address`, `urls`. Строгие опциональные
    ссылки: `Source.repository_id` (место хранения) и `Archive.repository_id`
    (учреждение). Отделено от `Archive`: цепочка хранения vs физическое учреждение.
26. `FactDate.calendar` — календарь (`gregorian`/`julian`/`unknown`, по умолчанию
    `unknown`); юлианский (старый стиль) для дореволюционных записей. Сравнения —
    в рамках одного календаря; календарь ортогонален точности и формулировке.
27. `Researcher` — не сущность, а конфигурация сервиса: `--researcher <person_id>` /
    env `GENODEX_RESEARCHER` (кто вёл сведения).
28. Детали имени: `PersonName.prefix` (фон/де) и `PersonName.suffix` (ст./мл.);
    прозвища/клички — многозначное поле `Person.nicknames []TextRef`.
