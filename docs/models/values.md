# Типы значений

Служебные типы-значения, используемые в полях сущностей.

## TextRef

Универсальный «текст-или-ссылка». Используется везде, где элемент может быть либо
строкой, либо ссылкой на сущность (списки, примечания, места).

Поля:
- `text` — отображаемая строка (обязательна, если не задана ссылка);
- `ref` — `id` целевой сущности (опционально);
- `type` — тип целевой сущности (опционально; задаётся вместе с `ref`).

Правила:
- Если `ref` пуст — элемент это просто текст, `type` тоже пуст.
- `type` и `ref` задаются вместе: `type` определяет, в каком хранилище/таблице искать
  объект по `ref` и как строить ссылку (страница веб / файл vault); по нему же
  выбирается тип данных при связывании объектов внутри хранилища.
- Текст не обязан совпадать с названием цели (например, слово в другом падеже) —
  как `[[файл|текст]]` в Obsidian или текст ссылки в HTML.

## NamedPeriod

Наименование с периодом действия (открытым с одной или обеих сторон).

Поля:
- `text` — наименование;
- `since` — начало периода (опционально);
- `until` — конец периода (опционально).

Применение: исторические наименования единиц адм. деления
(`AdministrativeDivision.renames`); потенциально — исторические названия церквей,
приходов, линий рода.

## FactDate

Структурированная дата с точностью. Реализация — конкретный Go-тип с методами
сравнения, **а не текст**: сравнения выполняются по компонентам даты, парсинг
формулировок происходит один раз при вводе, некорректные формулировки отсекаются
на этапе разбора.

Поля:
- `year` — год (обязателен, кроме `precision=unknown`);
- `month` — месяц (`0`, если неизвестен);
- `day` — день (`0`, если неизвестен);
- `precision` — `unknown` | `year` | `month` | `day` (верхняя известная точность);
- `modifier` — `exact` | `approx` | `before` | `after` | `between` (вид формулировки);
- `calendar` — `gregorian` | `julian` | `unknown` (по умолчанию `unknown`; юлианский —
  старый стиль дореволюционных записей; пустое значение эквивалентно `unknown`);
- `year_to`, `month_to`, `day_to` — верхняя граница для `modifier=between`
  (нижняя — в основных полях).

Интервал — не отдельная пара полей-«вилок», а `modifier=between` с двумя концами:
«не ранее… / не позднее…» покрываются `before`/`after`. Точность, вид формулировки
и календарь ортогональны (независимые признаки). Дата хранится так, как записана в
источнике. При сравнении юлианской и григорианской дат границы юлианской
переводятся в григорианские (через юлианский день); при `unknown` или совпадающих
календарях сравнение идёт «как есть». Разбор понимает суффиксы `ст. ст.` (юлианский)
и `н. ст.` (григорианский): `1917-10-25 ст. ст.` = `1917-11-07 н. ст.`.

Методы сравнения (по компонентам, без разбора строк):
- `Compare(other)` — раньше / позже / перекрытие / неопределимо;
- `SameYear(other)`, `SameMonth(other)` — совпадение года / месяца;
- точка vs диапазон: точная дата «перекрывает» значение с `approx`/`between`/
  `before`/`after`; если интервалы не пересекаются — определимо, иначе «не сравнить».

Примеры → представление:
- `1881` → `year=1881`, `precision=year`, `modifier=exact`;
- `около 1881` → `year=1881`, `precision=year`, `modifier=approx`;
- `1881-03` → `year=1881`, `month=3`, `precision=month`, `modifier=exact`;
- `до 1881` → `year=1881`, `precision=year`, `modifier=before`;
- `после 1881` → `modifier=after`;
- `между 1880 и 1882` → `modifier=between`, `year_to=1882`.

## PlaceRef

Указание на место. Это `TextRef`, у которого ссылка (если есть) ведёт на сущность
места: `AdministrativeDivision` | `Church` | `Parish`. Свободный текст — когда
сущности места ещё нет.

Поля:
- наследует поля `TextRef` (`text`, `ref`, `type`).

## Anchor

Привязка «где именно» к доказательству. Не один объект со всеми полями сразу,
а интерфейс: общий контракт (метод `AnchorType()` / дискриминатор `kind` для
сериализации) и отдельные реализации, каждая несёт только свои поля.

Реализации:
- `ArchiveAnchor` — скан страницы единицы учёта:
  - `node_id` — узел цепочки (единица учёта);
  - `document_id` — уточнение до документа внутри единицы (опционально);
  - `page` — номер скана/страницы;
  - `rect` — координаты области выделения на изображении (опционально);
- `FileAnchor` — файл с тайминговой привязкой:
  - `attachment_id` — вложение;
  - `timecode` — тайм-метка для аудио/видео (опционально);
- `URLAnchor` — внешняя ссылка:
  - `url` — адрес.

Правила:
- `Citation.anchor` — одна из реализаций либо пусто (тогда цитата — только текстовая
  расшифровка `Citation.text`);
- выбор реализации определяется типом источника (`Source.kind`), к которому относится
  цитата: архивный скан → `ArchiveAnchor`, аудио/фото/документ → `FileAnchor`, внешний
  источник → `URLAnchor`.

## SourceLink

Доказательство: связь «утверждение → цитата». Применяется к любому утверждению
любой сущности.

Поля:
- `citation_id` — `id` цитаты (строгая ссылка);
- `target_type` — тип сущности-утверждения;
- `target_id` — `id` сущности-утверждения;
- `reliability` — частная достоверность именно этого утверждения по этому источнику
  (скан достоверен для имён, но перс — возможный однофамилец);
- `role` — роль утверждения (опционально);
- `note` — примечание (опционально).

Цепочка доказательства — трёхуровневая: `SourceLink` → `Citation` → `Source`. См.
[Доказательства](evidence.md).
