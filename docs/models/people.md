# Люди и идентичность

## Person

`id`, `gender` (`unknown`/`male`/`female`), `names []PersonName`, `estates []TextRef`,
`titles []TextRef`, `nicknames []TextRef`, `notes []TextRef`, `sources []SourceLink`,
`private`.

- Все поля, кроме `id`, опциональны: персона может быть известна только по имени или
  даже только по полу.
- `PersonName` (вложенный): `surname`, `given`, `patronymic`, `type`
  (`main`/`birth`/`married`/`changed`/`pseudonym`), `prefix?` (фон/де),
  `suffix?` (ст./мл.), `since?`, `until?`.
  Одна персона может иметь несколько имён (девичья фамилия + фамилия по браку и т.п.).
  Каждое из полей имени — `TextRef` с мягкой ссылкой на словарную запись
  (`Surname`/`GivenName`/`Patronymic`): остаётся и строка из источника, и связь со
  словарём (для поиска и вариантов написания). Ссылка мягкая — словарной записи может
  ещё не быть.
- `nicknames` — прозвища/клички, несколько (`TextRef`: строка-написание или ссылка на
  словарную запись).
- `private` — приватизационный флаг.
- `gender` может быть неизвестен (например, известно только «7-ро детей»).
  Выводить пол из имени/отчества разрешается только для не-нейтральных имён
  (Андрей, Пелагея, отчество на `-на`/`-ич`); просторечные нейтральные имена
  (Женя, Саша, Мотя, Лёка) вывод запрещают. Авторитетен только `Person.gender` —
  выведенное значение лишь подсказка для проверки.
- `sources` — доказательства по атрибутам персоны (например, идентификация персоны по
  записи, где имя достоверно, а личность — вероятна).

## Relation (ребро графа родства)

`id`, `kind` (`blood` — кровное, `marriage` — брак/партнёрство, `adoption` — усыновление/опека,
`associate` — деятельная связь), `rel_type?`, `person_a`, `person_b` (строгие ссылки),
`since?`, `until?`, `sources []SourceLink`, `notes`, `private`.

- Кровное ребро — «родитель-ребёнок»; пол сторон берётся из `Person.gender`.
- Наименования родства (двоюродная сестра, тётя, племянник, сводный брат) **не
  хранятся**, а выводятся по графу рёбер как цепочки символов `F/M/D/S` (кровные) с
  расширением `P` (партнёр) и `A` (усыновление) для административных рёбер.
  Цепочка = кратчайший простой путь без повторов, запрет циклов.
  Цепочки и вывод наименований строятся только по `blood`/`marriage`/`adoption`;
  рёбра `kind=associate` в них не включаются.
- `rel_type` — вид деятельной связи для `kind=associate` (расширяемый список:
  `neighbor` — сосед, `colleague` — коллега по работе, `godparent` — крёстный,
  `witness` — свидетель, `friend` — друг, …); для остальных видов пусто.
- Родные / сводные братья и сёстры различаются сравнением цепочек от общего
  родителя: у родных общие цепочки через обоих родителей, у сводных
  (единоутробные/единокровные, `MS`/`MD`/`FS`/`FD`) — только через одного.
  Отметить: детально проработать отдельно при реализации вывода родства.
- `sources` — связь, как и событие, подтверждается доказательствами.

## Family (род / линия)

`id`, `name`, `members []TextRef`, `notes []TextRef`, `sources []SourceLink`, `private`.

- Член рода — либо ссылка на существующую `Person`, либо просто строка-имя (персона,
  о которой известно только имя/пол — и записи `Person` может не быть).
- Группирующая сущность: не дублирует рёбра `Relation`, но может быть дополнена ими.

## Словари: Surname, GivenName, Patronymic, Estate, Title

`id`, `canonical` (каноническая форма), `variants []TextRef`, `items []TextRef`,
`notes []TextRef`; у `GivenName` ещё `gender` (`male`/`female`/`neutral`).

- Словарные записи — отдельные сущности для нормализации и дедупликации
  (расхождения написания: Давыдово/Давидово, варианты имён и фамилий).
- `variants` — варианты написания одного и того же имени (Иоанн↔Иван): ссылки на
  записи-варианты или просто строка-написание; между вариантами — взаимные ссылки.
  У мест и адм. деления варианты хранятся строками в самой сущности
  (см. [Места](places.md)).
- `items` — список носителей/употреблений: элемент может быть текстом **или** ссылкой на
  сущность, которой может ещё не существовать. Если сущность создана — элемент связан
  с ней (в vault — ссылка на файл, в веб — ссылка на страницу).
- У каждого имени (`GivenName`) обязателен признак пола `gender`:
  `male` / `female` / `neutral` (Женя, Саша, Мотя — нейтральные; вывод пола по ним
  запрещён).
- **Поиск** по словарям и адм. делению (фамилии, имена, отчества, названия нас.
  пунктов и адм. единиц): жёсткие связи `type`+`id` (например, фрагмент→персона)
  ранжируются выше всех; затем точное совпадение (`canonical` или любой вариант);
  совпадение по вариантам написания — с меньшим приоритетом.
