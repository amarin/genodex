# Архивная цепочка

Цепочка от наименования архива до цитируемого фрагмента. В разных архивах разная
иерархия хранения (Фонды/Описи/Дела, Фонд/Шкаф/Полка/Карточка и др.), поэтому состав
и имена уровней параметризуются архивом через систему иерархии — по аналогии с
системами административного деления (см. [places.md](places.md)).

```
Archive (имя + система иерархии)
 └ ArchiveNode — рекурсивные уровни (fond → opis → delo | fond → shkaf → polka → kartochka)
    └ последний уровень системы = единица учёта (дело, карточка, …)
       └ ArchiveDocument — документ внутри единицы (метрическая книга за годы…)
          └ Attachment — скан страницы/листа (page + rect, см. evidence.md)
```

## Archive

`id`, `name`, `system?`, `repository_id?` (строгая), `notes []TextRef`, `sources`, `private`.

- `system` — система иерархии хранения архива (см. `ArchiveHierarchySystem`);
  указывает ожидаемые уровни и какой уровень считается единицей учёта.
- Архив без системы ведётся без уровневого гайда (иерархия свободная).
- `repository_id` — учреждение, где архив физически расположен (см. `Repository`).
  Типичный случай — один архив на одну запись репозитория; пусто, если запись
  репозитория не заведена.

## ArchiveHierarchySystem

> **Статус: проектное описание, в коде не реализовано.** Сейчас `Archive.System` —
> обычный `*TextRef` (текст системы), встроенных систем иерархии нет;
> `internal/definitions` содержит только словари административного деления.

`name`, `node_types []ArchiveNodeType` (упорядоченный список: верхний уровень → нижний).
Значения уровней — ASCII-слаги (`fond`, `opis`, `delo`, `shkaf`, `polka`,
`kartochka`); русские названия уровней — данные системы для отображения.

- Не сущность хранилища, а built-in данные в `internal/definitions` (как системы
  административного деления):
  - «Фонды/Описи/Дела» — `fond → opis → delo` (фонд → опись → дело; типичный
    госархив);
  - «Фонд/Шкаф/Полка/Карточка» — `fond → shkaf → polka → kartochka`
    (фонд → шкаф → полка → карточка; картотека, напр. РГВА);
  - другие системы добавляются по мере необходимости.
- Последний элемент списка — единица учёта: то, что цитируется как доказательство
  (дело, карточка, лист, …).

## ArchiveNode

`id`, `type (ArchiveNodeType)`, `archive_id` (строгая), `parent_id?` (строгая),
`label` (номер/шифр), `name?` (заголовок), `since?`, `until?`, `parish (TextRef?)`,
`settlements []TextRef`, `notes []TextRef`, `sources`, `private`.

- Единый рекурсивный узел, как `AdministrativeDivision`: уровень, а не конкретная
  сущность. `type` — значение открытого enum'а (формат `[a-z][a-z0-9_-]*`),
  уровень системы иерархии архива; отображаемое название уровня — данные системы
  иерархии; соответствие уровня системе архива проверяют сценарии.
- `archive_id` — строгая (денормализованная) ссылка на архив: навигация по всем
  узлам архива без обхода цепочки.
- `parent_id` — строгая ссылка на родителя (другой `ArchiveNode`); пусто у первого
  уровня. Глубина не зафиксирована: система задаёт ожидаемые уровни, но допустимы
  отклонения (подпапки дел, нестандартные архивы).
- `label` — шифр/номер единицы («дело №264», «опись №6», «шкаф 3», «карточка 12»);
  на нём же строится читаемый адрес (`gako-f33-o6-d264`).
- `name`/`since`/`until`/`parish`/`settlements` — показательны для единицы учёта:
  дело имеет собственный заголовок, годы подшивки и географическую привязку; для
  промежуточных уровней обычно пусты.
- Единица учёта — узел последнего уровня системы (конвенция).

## ArchiveDocument

`id`, `unit_id` (строгая), `title`, `kind?`, `since?`, `until?`, `parish (TextRef?)`,
`settlements []TextRef`, `notes []TextRef`, `sources`, `private`.

- Отдельная сущность под единицей учёта: дело часто — подшивка нескольких
  документов (метрические книги за разные годы и/или разных приходов).
- `unit_id` — строгая ссылка на единицу учёта (узел).
- `kind` — вид документа (метрическая книга / исповедная ведомость / ревизская
  сказка / карточка / …); позже, возможно, станет словарём.
- Собственные заголовок, период и география: «Метрическая книга Николаевской ц.
  с. Давыдово за 1880–1882» внутри дела за 1880–1890.
- Дело из одного документа — единица + один `ArchiveDocument`.
- Ровно один уровень вложенности: ниже документа — только сканы/страницы
  (`Attachment`), вложенных документов нет.

## Attachment (сканы)

См. [evidence.md](evidence.md). Привязка к узлу (`node_id`, строгая), опционально
уточнение до документа (`document_id`). Страница/лист/скан детализируются полями
`page` и `anchor.rect`.

## Repository

`id`, `name`, `type` (`archive`/`library`/`museum`/`private`/`other` + открытый),
`address?`, `urls []TextRef`, `notes []TextRef`, `sources`, `private`.

- Учреждение-хранилище (архив, библиотека, музей, частный фонд) с контактными данными —
  где физически находится источники.
- Привязки: `Source.repository_id` — место хранения источника (см. [Доказательства](evidence.md)),
  `Archive.repository_id` — учреждение, в котором расположен архив. Обе ссылки строгие
  и опциональные.
- Отделено от `Archive`: архив — цепочка хранения с системой иерархии, репозиторий —
  физическое учреждение; в типичном случае на один архив приходится одна запись
  репозитория.
