# Архитектура и структура проекта

## Обзор

Сервис построен слоями: доменные модели → хранилище → внешние интерфейсы (MCP и HTTP API) → веб-SPA. Все слои живут в одном процессе, одного бинарника достаточно для запуска.

```
                    ┌──────────────────────────────┐
                    │   cmd/genealogy-mcp/main.go   │  маршрутизация
                    │  /mcp  /api  /static  /       │
                    └───────┬──────────┬────────────┘
             ┌──────────────┤          ├──────────────┐
             ▼              ▼          ▼              ▼
    internal/mcp    internal/httpapi          web (embed + React SPA)
    (MCP-тулы)          (/api-роуты)          /static/ и / для людей
             └──────────────┼──────────┘
                            ▼
                 internal/store/store.go
                 (in-memory, thread-safe)
                            ▼
                 internal/entity (доменные модели)
                 internal/definitions (встроенные данные)
```

## Структура каталогов

| Путь | Назначение |
|------|-----------|
| `cmd/genealogy-mcp/main.go` | Точка входа: HTTP-сервер, маршрутизация, graceful shutdown. Флаги `-p` и `-web`. |
| `internal/entity/` | Доменные модели — определения типов для всех сущностей сервиса (человек, нас. пункт, церковь, приход, губерния, уезд, волость, архив, фонд, опись, дело, событие, брак, источник и др.) без детализации по типам. JSON-теги моделей задают форму JSON в `/api` и MCP-тулах. |
| `internal/store/store.go` | Общее in-memory хранилище всех сущностей. Thread-safe (`sync.RWMutex`), однотипные методы `Get` / `Save` / `List` для каждой сущности. Используется и MCP, и HTTP API. |
| `internal/definitions/` | Встроенные доменные определения. `russia/` — системы административного деления (Российская империя 19 в., СССР). |
| `internal/mcp/` | Слой MCP на `github.com/mark3labs/mcp-go`. `NewServer` создаёт `server.MCPServer`, регистрирует тулы. Транспорт — Streamable HTTP. |
| `internal/httpapi/` | Слой HTTP API: JSON-роуты `/api/*` (health, settlements). Использует тот же `store`, что и MCP. |
| `web/` | Фронтенд: Vite + React 18 + antd. `src/` — исходники, `dist/` — результат сборки, `embed.go` — `//go:embed` и раздача. |
| `docs/` | Документация проекта. |

## Веб-раздача

- Фронтенд собирается в `web/dist` командой `npm run build`.
- `web/embed.go` встраивает `web/dist` в бинарник через `//go:embed all:dist`.
- Флаг запуска `-web` задаёт режим:
  - `prod` (по умолчанию) — файлы из встроенной в бинарник FS;
  - `dev` — файлы читаются с диска из `web/dist` (удобно при разработке фронта без пересборки Go).
- Vite-конфиг использует `base: '/static/'`, поэтому собранные ассеты отдаются под `/static`, а `/` — SPA-страница `index.html` с fallback на неё для client-side роутов.

## Поток данных

1. Клиент (MCP-клиент, браузер, curl) обращается к одному из маршрутов.
2. Хендлер `internal/mcp` или `internal/httpapi` обращается к `internal/store`.
3. `Store` работает с моделями из `internal/entity`.
4. Результат сериализуется в JSON и возвращается клиенту.
