# Поиск по базе

> **Статус: дизайн согласован, не реализовано.** Раздел фиксирует итоги обсуждения
> от 2026-09-24. Реализация разбита на подпроекты P1–P7 (раздел P в
> [todo.md](../todo.md)); каждый получает свой план в `docs/plans/`. Сетевые
> функции (поиск у других узлов, точки интереса) в раздел не входят — см.
> [exchange/](../exchange/index.md).

## Проблема

Сейчас поиск — префиксный, по одному термину, отдельно для каждого типа сущности
(`<entity>_search`, `/api/<entities>/search` поверх `Store.Search` и таблицы
`search_index`). Морфология не учитывается: «Покровскаго» не находит «Покровский»,
«Иванову» не находит «Иванов». Длинные тексты (цитаты, заметки, пометки) в индекс не
попадают по словам: `Citation.text` лежит одним термином, `Note.text` и пометки
`Notes` не индексируются вовсе. Глобального поиска по всем сущностям нет.

Нужны три сценария, в порядке приоритета:

1. **Навигация** — одна строка в шапке, мгновенный переход к нужной записи любого
   типа;
2. **Исследование** — всё, что в базе связано с именем или местом, с фрагментами
   текста, где оно встречается;
3. **Ввод** — пикеры в формах, устойчивые к вариантам написания.

Этот раздел проектирует **механизм** (общий для всех трёх) и **глобальную
навигацию** с исследовательской страницей результатов.

## Постулаты

- Тексты — **в основном русские, орфография смешанная**: современная и
  дореформенная («Ивановъ», «Покровскій», «Ѳеодоръ»), с сокращениями писцов
  («кр-нин», «с.», «дер») и титлами. Не-кириллические тексты не индексируются и не
  ищутся — пока не рассматриваются вовсе.
- **Морфология — библиотека [gomorphy](https://github.com/amarin/gomorphy)**
  (аналог pymorphy2 на Go, словарь OpenCorpora в компактном бинарном формате,
  лемматизация, предсказание, нечёткий поиск, несколько словарей одновременно).
  Недостающие функции дорабатываются в библиотеке; цикл «запрос → реализовано»
  считается быстрым.
- **Никаких внешних сервисов.** Всё работает внутри одного бинарника и одной SQLite.
- **Словари — живой набор файлов, а не часть релиза.** Базовый словарь поставляется
  с genodex; дополнительные (фамилии, имена, отчества, губернии и уезды, сокращения)
  загружаются, составляются, исправляются, включаются и выключаются в процессе
  работы и передаются как файлы.

## Принятые решения

| № | Решение | Следствие | Документ |
|---|---|---|---|
| 1 | **Нечёткость — три уровня:** морфология и орфография, варианты по словарям — всегда; «похожие» (опечатки, искажения) — отдельный режим, когда точных совпадений мало | точная выдача объяснима; шум от «похожих» отделён секцией | [ranking](ranking.md) |
| 2 | **Лемматизация — при индексации**, в индекс идёт нормальная форма; запрос разбирается на слова и сводится к леммам тем же нормализатором | запросы к базе простые; поиск по всем словоформам OR-ом отвергнут как чудовищный по форме и скорости | [storage](storage.md) |
| 3 | **Индекс A′:** постинг хранит и лемму, и id исходной формы — `postings(lemma, form, entity, field, …)` | точность «та же форма / та же лемма» видна в запросе; ошибочный разбор исправляется точечно, без переразбора текстов | [storage](storage.md) |
| 4 | **Словари — папка** `<data>/dicts/`: встроенный базовый словарь плюс сколько угодно пользовательских; подключаются и отключаются на ходу; `--dicts DIR` переопределяет папку | смена словарей не ломает индекс: сверка по формам в фоне; дубли лемм от двух словарей схлопываются | [normalization](normalization.md) |
| 5 | **Один нормализатор** на поиск, NER (E9), поиск дублей (E10) и сопоставление (F5) | требование [matching](../exchange/matching.md#два-этапа-отбор-и-сравнение): два нормализатора разойдутся | [normalization](normalization.md) |
| 6 | **Индексация асинхронная:** в транзакции сохранения пишется только задание (outbox), индекс строит фоновый воркер | запись находится через секунды после сохранения; падение процесса индексацию не теряет | [storage](storage.md) |
| 7 | **Индекс — часть базы**, по умолчанию бэкапится; `backup --no-index` для уменьшения размера, после восстановления перестраивается | `verify` умеет сверять индекс с данными | [storage](storage.md) |
| 8 | **Подъём к главной сущности:** совпадение в заметке, цитате, событии, имени показывается как довод внутри главной сущности (персона, место, источник, документ…) | связи — граф: при нескольких главных берётся первая по **настраиваемому порядку типов**, остальные — подсказкой «также в…» | [ranking](ranking.md) |
| 9 | **Ранжирование ступенями, а не суммой весов:** покрытие слов → качество совпадения → класс поля → прямота → порядок типа | каждый результат объясняется доводами, как в [matching](../exchange/matching.md#правила-а-не-обученная-модель) | [ranking](ranking.md) |
| 10 | **Словарная запись — результат** («Фамилия: Кузнецов») с группой действий внутри; для фамилии без записи в словаре — виртуальный результат с действием «Добавить в словарь» | действия — это готовые запросы с фильтром и пустым текстом | [ranking](ranking.md) |
| 11 | **Фильтры-области:** сущность-фильтр плюс потомки по иерархии; главная сущность проходит, если её кластер связан с областью одним ребром | один механизм для фильтров, действий словарных результатов и кнопки «Искать здесь» на страницах сущностей | [filters](filters.md) |
| 12 | **Приватность — на обоих концах подъёма:** публичная выдача скрывает приватную подчинённую и приватную главную; владелец видит всё | совпадение в приватной заметке не выдаёт публичную персону | [ranking](ranking.md) |
| 13 | **Выпадающий список — всегда пресет «Строго»**; страница результатов — пресеты «Строго / Обычно / Широко» и тонкая настройка | у каждой опции — справка «если включено / если выключено» с наблюдаемым эффектом | [ui](ui.md) |
| 14 | **Поиски по типам переводятся на новый движок без смены контракта**; старые `search_index` и `Store.Search` удаляются | один механизм; пикеры и списки получают морфологию бесплатно | [storage](storage.md) |
| 15 | **Новые контракты:** `GET /api/search` и MCP-тул `search` | глобальная навигация для веба и агентов | [ranking](ranking.md#контракты) |

## Конвейер

```
сохранение сущности
   → задание в outbox (в той же транзакции)
   → воркер: тексты полей → нормализатор (орфография, токены, сокращения, леммы)
   → postings(lemma, form, entity, field) + рёбра подъёма и связей (search_link)

запрос
   → нормализатор: слова, стоп-слова по частям речи, леммы, последнее слово — префикс
   → постинги по леммам (и префикс по формам)
   → подъём к главным сущностям, фильтры-области, приватность
   → ранжирование ступенями, доводы с фрагментами, путь по иерархии
   → «похожие», если точных мало
```
