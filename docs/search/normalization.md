# Нормализатор и словари

> Часть раздела [Поиск по базе](index.md). Подпроекты P1 (нормализатор, словари) и
> P7 (управление словарями в UI).

Нормализатор превращает текст в набор токенов для индекса и запрос — в набор
токенов для поиска. **Он один** на поиск, извлечение сущностей
([E9](../ux/extraction.md)), поиск дублей (E10) и сопоставление с партнёрами
([F5](../exchange/matching.md#два-этапа-отбор-и-сравнение)): два нормализатора
разойдутся, и поиск начнёт находить не то, что сопоставление.

**Исходный текст не меняется.** Нормализация нужна только для индекса и сравнения;
на экране — всегда текст как он записан, фрагменты строятся по оригиналу.

## Слои

```
текст → орфография → токены → сокращения → леммы (gomorphy) → токены индекса
```

### 1. Орфография

Посимвольно, до токенизации:

| Что | Как |
|---|---|
| регистр | нижний |
| ё | е |
| ѣ | е |
| і, ї, ѵ | и |
| ѳ | ф |
| ѡ | о |
| ꙋ, ѹ | у |
| ѧ | я |
| ѯ, ѱ | кс, пс |
| конечный ъ | отбрасывается («ивановъ» → «иванов»); ъ внутри слова остаётся |
| надстрочные знаки (титла, ударения, придыхания), диакритика | отбрасываются (Unicode-разложение, знаки категории Mark) |

Таблица — данные в коде с тестом на каждую строку. Её изменение меняет формы в
индексе и требует полной переиндексации (`genodex reindex`, см.
[storage.md](storage.md#сверка-и-переиндексация)); в базе хранится версия правил.

### 2. Токенизатор

- Слово — непрерывная последовательность кириллических букв. Не-кириллические
  токены отбрасываются (постулат раздела).
- **Числа** индексируются как формы без леммы: год в запросе («Покровское 1834»)
  находит его в тексте.
- **Дефис внутри слова:** сначала целиком проверяется по словарю сокращений
  («кр-нин», «с-цо»). Не сокращение — составное слово: индексируется целиком и по
  частям («санкт-петербург», «санкт», «петербург»).
- **Точка после слова** — признак кандидата в сокращения («с.», «губ.»). Сама точка в
  форму не входит, но признак передаётся следующему слою.
- Позиции слов в индекс не пишутся (см. [storage.md](storage.md#минусы-и-меры)); для
  фрагментов текст токенизируется заново.

### 3. Сокращения

Словарь сокращений — **один из тематических словарей** в папке словарей (ниже):
форма сокращения → лемма(ы) полного слова. Три вида записи:

| Вид | Примеры |
|---|---|
| с точкой | «с.» → село, «д.» → деревня, «ц.» → церковь, «губ.» → губерния, «крест.» → крестьянин |
| с дефисом | «с-цо» → сельцо, «кр-нин» → крестьянин, «вол-ть» → волость |
| без знаков | «дер» → деревня, «губ» → губерния |

Правила:

- Сокращение без знаков может совпасть с настоящим словом («губ» — форма «губа»):
  тогда записываются **обе** леммы как неоднозначный разбор; различает
  ранжирование, позже — NER по контексту.
- Самые короткие сокращения многозначны («с.» — село, сын, сестра, священник).
  Однобуквенные сокращения распознаются только с точкой и в индекс идут с признаком
  неоднозначности (понижены в ранжировании).
- «с» без точки — предлог, стоп-слово.
- Словарь пополняется пользователем и передаётся как файл. Обмен наработанными
  словарями с доверенными узлами — пункт программы F, здесь не проектируется.

### 4. Леммы

Каждая форма разбирается через подключённые словари gomorphy (`MultiDictionary`).
Результат — **множество лемм** с признаками:

| Признак | Когда |
|---|---|
| `ambiguous` | лемм больше одной («стали» → сталь / стать; «вера» → имя / слово) |
| `predicted` | слова нет в словарях, лемма предсказана по окончанию |
| `unknown` | нет ни разбора, ни предсказания — лемма = сама форма (псевдолемма) |
| `abbrev` | лемма получена из словаря сокращений |

Одинаковые леммы из разных словарей схлопываются (два почти одинаковых словаря
одновременно — нормальная ситуация при замене словаря).

**Набор словарей зависит от поля.** Поля имени (`PersonName`) разбираются
словарями имён, фамилий и отчеств, поля места — словарями топонимов и базовым,
свободный текст — всеми. Это главная мера против омонимии имён и обычных слов
(«Вера, Надежда, Любовь», «Кузнец, Мороз, Орёл»).

**Варианты по словарям — не морфология.** «Авдотья» и «Евдокия» — разные леммы;
их связывает запись словаря базы (`GivenName.Variants`). Вариант раскрывается при
поиске: лемма запроса → запись словаря → леммы всех её вариантов → постинги.
Раскрытие даёт несколько лемм, а не десятки словоформ, и помечается в доводах как
«вариант по словарю».

### 5. Стоп-слова

Отбрасываются по тегам части речи gomorphy (предлог, союз, частица, междометие),
если **все** разборы слова — служебные. Слово с точкой — кандидат в сокращения, не
в стоп-слова. Списка стоп-слов в коде нет.

### Разбор запроса

Тем же нормализатором, с двумя отличиями:

- **последнее слово без пробела после него — незаконченное:** ищется как префикс по
  таблице форм базы, а не по лемме («Покро» → «покровское», «покровский»…);
- слово запроса, которое уже встречалось в базе, берёт леммы из индекса без
  обращения к словарям; иначе — через gomorphy. Без словарей поиск **деградирует, но
  не ломается**: остаются точная форма, префикс и инфикс по формам базы.

## Словари

### Папка словарей

- Каталог `<data>/dicts/` (переопределяется `--dicts DIR`). Каждый файл — словарь
  gomorphy в бинарном формате.
- **Базовый словарь** (OpenCorpora) встроен в бинарник (`//go:embed`) и открывается
  из памяти, без распаковки на диск. Поставляется с релизом genodex, но может быть
  отключён или дополнен как любой другой.
- Список подключённых словарей, их порядок и состояние (включён / выключен)
  хранятся в базе. Подключение и отключение — на ходу, без перезапуска.
- **Лицензия:** словарные данные OpenCorpora распространяются по CC BY-SA; при
  встраивании нужна атрибуция (в `--version`, `/api/health` или странице «О
  программе»). Проверить при реализации P1.

### Виды словарей

| Словарь | Откуда | Меняется |
|---|---|---|
| базовый (OpenCorpora) | встроен | с релизом genodex или заменой пользователем |
| сокращения | встроенный стартовый набор + пользователь | пополняется |
| губернии, уезды, волости | файл, наполняется один раз | почти никогда |
| фамилии, имена, отчества | **генерируются из записей базы** (`Surname`, `GivenName`, `Patronymic` с `Variants`) и/или файлы | при изменении словарных записей — пересборка в фоне |
| пользовательские | составлены или получены файлом | по необходимости |

Словари, сгенерированные из базы, закрывают то, что уже требует
[extraction.md](../ux/extraction.md#движок-без-llm) («словари из собственных данных,
обновляются вместе с данными»).

### Безопасная замена

Словарь можно проверить до переключения: подключить новый рядом со старым,
проверить разборы (P7), затем отключить старый. На время перекрытия дубли лемм
схлопываются (выше).

### Версия набора словарей

Хэш от (подключённые словари, их порядок, хэши содержимого) хранится в базе. Смена
версии ставит в очередь **сверку**: пересчёт лемм по таблице форм и точечная правка
постингов — без переразбора текстов ([storage.md](storage.md#сверка-и-переиндексация)).

### Неизвестные слова

Фамилии, названия деревень, редкие имена часто отсутствуют в OpenCorpora — а это
самые ценные для генеалогии слова. Меры, по нарастанию:

1. предсказанная лемма (`predicted`) с пониженным весом;
2. пополнение словарей фамилий/имён/отчеств/топонимов из записей базы;
3. формы без разбора собираются в список «неизвестные слова» с предложением
   добавить в локальный словарь; gomorphy предсказывает парадигму для начального
   заполнения (P7).

## Запросы в gomorphy

| Функция | Зачем |
|---|---|
| открытие словаря из `[]byte` / `io.ReaderAt` | встроенный базовый словарь без распаковки на диск |
| нечёткий поиск по произвольному или инкрементальному набору слов | «похожие» по лексике базы (фамилии, которых нет в словарях) — [ranking.md](ranking.md#похожие) |
| признак «предсказанная лемма» в результате разбора | признак `predicted` |
| дедупликация результатов в `MultiDictionary` | два почти одинаковых словаря при замене |
| быстрая пересборка небольших словарей | словари, сгенерированные из записей базы |
