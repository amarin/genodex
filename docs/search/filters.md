# Фильтры-области

> Часть раздела [Поиск по базе](index.md). Подпроект P5.

Найденная сущность (уезд, волость, фонд, источник, персона, словарная запись)
становится **фильтром-чипом**: следующий запрос ищет только связанное с ней. Вход в
поиск с таким фильтром есть на странице каждой сущности, которая может быть фильтром
(почти каждой), — кнопка «Искать здесь».

## Принцип

1. **Область** фильтра — сущность X плюс её **потомки по иерархии**.
2. **Главная сущность проходит фильтр**, если хоть одна сущность её **кластера**
   имеет **прямое ребро** с областью. Кластер — сама главная плюс всё, что к ней
   поднимается ([ranking.md](ranking.md#правила-подъёма)).

Новых правил обхода не вводится: кластер уже задан подъёмом, «прямая связь» — одна
таблица рёбер `search_link` ([storage.md](storage.md#схема)).

Пример: персона проходит фильтр «волость N», если её проживание или событие с её
участием находится в деревне этой волости.

## Иерархии (потомки)

| Фильтр | Потомки |
|---|---|
| `AdministrativeDivision` | единицы ниже по `ParentID` (волость → деревни) |
| `Repository` | его архивы и всё ниже |
| `Archive` | узлы архива, их документы и вложения |
| `ArchiveNode` | узлы ниже по `ParentID`, их документы и вложения |
| `Note` | дочерние заметки по `ParentID` |
| остальные | только сама сущность |

Потомки вычисляются рекурсивным запросом: иерархии маленькие.

## Рёбра

| Вид ребра | Откуда → куда |
|---|---|
| `rise` | подчинённая → главная (подъём) |
| `place` | `Residence.PlaceID`, `Event.Place`, `Parish.Settlements`, `Church.Settlements`, `Church.Parish` / `Parish.Church`, `ArchiveNode.Parish/Settlements`, `ArchiveDocument.Parish/Settlements` → место |
| `archive` | `ArchiveDocument.UnitID`, `Attachment.NodeID/DocumentID`, `Citation.Anchor` (скан в деле или вложение) → узел, документ, вложение |
| `evidence` | `SourceLink`: цитата → сущность-утверждение; `Citation.SourceID` → источник |
| `member` | `Family.Members`, участники `Event`, стороны `Relation` → персона |
| `dict` | `PersonName` и прочие `TextRef` со ссылкой на словарную запись → запись словаря |

Пример цепочки для архива: фильтр «фонд F» → область содержит дела и документы →
цитата со сканом в деле имеет ребро `archive` → её кластер (источник, а при опции —
цели `SourceLink`) проходит фильтр. Так находятся «все персоны, упомянутые в делах
этого фонда».

## Опции

| Опция | Умолчание | Смысл |
|---|---|---|
| правопреемники делений | **включено** | область деления включает предшественников и преемников по `Successors` (переименования, слияния) — частый случай в генеалогии |
| родственники для фильтра-персоны | **выключено** | «вокруг Ивана Кузнецова» включает родственников через `Relation` на один шаг; выключено, иначе фильтр быстро расползается |

Справка к опциям — по правилам [ui.md](ui.md#тонкая-настройка-и-справка).

## Комбинация и пустой текст

- Несколько фильтров объединяются через **И** («волость N» и «фамилия Кузнецов»).
- Текст запроса может быть **пустым** — тогда поиск становится просмотром
  отфильтрованного. Действия словарных результатов («Все персоны с фамилией
  Кузнецов») — это пустой текст + фильтр по записи словаря + тип.
- Фильтр по **виртуальной** словарной записи (фамилия без записи в словаре) —
  совпадение леммы в полях имени, а не ребро `dict`.

## Интерфейс

- Чип фильтра показывает тип и подпись с путём по иерархии («Волость N · уезд M»);
  чип снимается, к нему добавляется второй.
- Найденная сущность в выдаче, которая может быть фильтром, имеет действие «Искать
  здесь».
- Кнопка «Искать здесь» на странице сущности открывает страницу результатов с этой
  сущностью в чипе и пустым текстом.

## Ограничения

- Иерархия делений (`ParentID`) одна и не зависит от времени: волость, переходившая
  между уездами, попадает только в текущего родителя. Частично закрывается опцией
  правопреемников; полноценная временная иерархия — вне объёма.
