# Рабочий контекст ввода (веб)

> **Статус: обсуждение, не реализовано.** См. [обзор раздела](index.md).

## Идея

При вводе почти всегда есть контекст предыдущих действий: пользователь посмотрел
деревню и пошёл добавлять персону; создал недостающие Архив → Фонд → Опись →
Дело и теперь вносит фрагменты. Данные контекста должны предзаполнять поля
и поднимать варианты вверх списков выбора.

## Явный и неявный контекст

Два разных по силе сигнала — обращаться с ними нужно по-разному.

| | Неявный | Явный (закреплённый) |
|---|---|---|
| Откуда | недавно открытые или созданные сущности | пользователь закрепил: «работаю с делом Ф.123 Оп.4 Д.56» |
| Надёжность | низкая: заход для сравнения, случайный переход, результат поиска | высокая |
| Что делает | поднимает варианты вверх списков, подсвечивает | предзаполняет поля с пометкой «из контекста» |
| Автоприменение | **никогда** | только предзаполнение, снимается одним кликом |

Пример из обсуждения: после страницы населённого пункта форма новой персоны
*предлагает* связь с ним (неявный контекст), но не создаёт её сама.

## Модель

- Набор слотов по типам: `archive_node`, `archive_document`, `page` (лист),
  `place`, `person`, `period`, `source`, `record_type`.
- У слота: значение, происхождение (`pinned` / `recent`), время установки.
- **Архивная цепочка не хранится целиком.** `ArchiveNode` иерархичен
  (`ParentID`), поэтому достаточно самого глубокого узла, а Архив/Фонд/Опись
  выводятся. Отсюда же правило согласованности: выбор дела из другого архива или
  фонда сбрасывает нижележащие слоты.
- Контекст **виден** в UI — панель чипов над формой, каждый чип снимается.
  Скрытое состояние, которое влияет на ввод, — источник ошибок.

## Что выводится из контекста

- Для фрагмента (`Citation`) или записи документа: вся цепочка до дела
  (`ArchiveAnchor.NodeID`, `DocumentID`), источник, лист.
- **Период** из `ArchiveNode.Since/Until` или `ArchiveDocument.Since/Until` —
  только по умолчанию: это период дела, а не дата факта.
- **Лист** — режим последовательного ввода: «тот же лист» / «следующий лист» /
  «оборот». Зависит от правки модели листа
  ([archive-anchor-folio.md](archive-anchor-folio.md)).
- **Место** — кандидаты из `ArchiveNode.Parish`/`Settlements` поднимаются
  вверх списка мест.
- **Тип записи** (метрика, исповедная ведомость, ...) — выбирается один раз на
  серию ([records.md](records.md)).

## Хранение и жизненный цикл

- **На уровне вкладки** (sessionStorage и/или параметры URL): две вкладки с
  разными делами не должны перетирать контекст друг друга. Недавние значения
  (неявный контекст) можно держать в localStorage общими.
- **Устаревание:** срок жизни у неявных слотов; для закреплённого контекста
  при возвращении — явное «продолжить с делом X?».
- **Инвалидация:** удалённая сущность сбрасывает свой слот и нижележащие.
- Серверная сессия для веба не нужна; для MCP — отдельный вопрос
  ([mcp-context.md](mcp-context.md)).

## Сопутствующие помощники (та же фаза)

- **Создание в поле выбора.** Нет описи — она создаётся прямо из поля «Опись»
  в модальном окне, родитель подставлен из контекста; без ухода со страницы.
  Закрывает половину сценария «сначала создай всю цепочку».
- **Разбор архивного шифра.** Вставка строки «ГАКО Ф.123 Оп.4 Д.56 Л.12об.» →
  поиск цепочки в базе → предложение создать недостающие звенья → установка
  контекста. Узкий детерминированный разборщик: сокращения архивов (из данных
  `Archive`), `ф.`/`оп.`/`д.`/`л.`/`об.`, литеры в номерах (`Д.56а`), диапазоны
  листов (`Л.12–14об.`).
- **Недавние и частые** значения вверху каждого поля выбора.

## Открытые вопросы

- Как показывать контекст на узком экране.
- Нужен ли «сброс всего контекста» как явное действие и где.
