# Разметка текста: упоминания и обратные ссылки

> **Статус: обсуждение, не реализовано.** См. [обзор раздела](index.md).

## Идея

Упоминания в текстовых полях (найденные извлечением или отмеченные вручную)
подсвечиваются в UI и становятся ссылками на сущности; исходный текст не
меняется. Механизм универсальный: отдельная сущность хранит «где в тексте» и
«на что указывает», API отдаёт разметку вместе с данными сущности.

Механизм **не зависит от извлечения**: ручная разметка («выделил текст →
связать с…») полезна сама по себе, а NER — лишь ещё один источник
предложений. Строится раньше извлечения.

## Модель: Mention

```
id
host_type, host_id, field      — где текст; field — путь поля (text, notes[2].text, values[fio])
start, end                     — позиция в кодовых точках Unicode (после NFC)
exact, prefix, suffix          — цитата и окружение для переякорения
target_type, target_id         — цель; пусто = упоминание не связано
status                         — suggested | confirmed | rejected
origin                         — manual | rule | context
confidence                     — для предложений
fact_ref (опц.)                — факт/связь, порождённые этим упоминанием
```

Образец — W3C Web Annotation Data Model (`TextPositionSelector` +
`TextQuoteSelector`).

## Сложности

- **Единица позиции.** Go считает байты, JS — UTF-16. Фиксируем кодовые точки
  и NFC-нормализацию на входе, иначе ѣ, ё и комбинирующие ударения сдвигают
  разметку. Преобразование — на границе API.
- **Правка текста.** При сохранении разметка переякоряется по
  `exact` + `prefix`/`suffix` (diff старого и нового текста). Не нашлась —
  упоминание помечается «потерянным» и уходит на подтверждение, но не
  удаляется молча.
- **Markdown (`Note.Text`).** Позиции считаются по исходнику; при рендере
  ссылки вставляются преобразованием текстовых узлов mdast (плагин remark), а не
  подстановкой в HTML. Упоминание, пересекающее границу форматирования,
  рендерится частями.
- **Перекрытия.** Пересечения запрещены, вложенность разрешена
  («дер. Лягушкиной Н-ского уезда» → общий спан места и вложенный уезд);
  при рендере внешняя ссылка, внутренняя — подсказкой.
- **Приватность.** Упоминание приватной сущности в публичном режиме
  (`Access`) отдаётся без цели — просто текстом; иначе раскрывается сам факт
  существования сущности.
- **Удаление цели.** Упоминание становится несвязанным, текст остаётся;
  удаление цели упоминания не блокируют (в отличие от `InUseError`).
- **API.** В DTO сущности — `annotations` по полям плюс пакетно разрешённые
  подписи целей (для подсказок, без N+1). Отклонённые упоминания в ответ для
  отображения не попадают.

## Обратные ссылки

Индекс упоминаний по цели даёт на странице любой сущности раздел
«упоминается в»: список текстов с окружением и переходом. Для исследователя это,
возможно, ценнее самой подсветки (аналог обратных ссылок Obsidian).
Несвязанные упоминания с тем же нормализованным текстом — подсказка «возможно,
тоже про это».

## Связь с TextRef

`TextRef` по сути — упоминание, занимающее весь элемент списка. Сейчас не
трогаем; возможная унификация — отдельный вопрос после внедрения Mention.

## Открытые вопросы

- Для каких полей разметка включена (все текстовые или по списку).
- Хранить ли `rejected` бессрочно (память отказов для извлечения).
- Нужна ли разметка упоминаний в `raw`-значениях граф записей или там
  достаточно `ref` на графу.
