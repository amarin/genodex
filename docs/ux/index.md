# Автоматизация ввода: пользовательский опыт

> **Статус: обсуждение, не реализовано.** Раздел фиксирует итоги обсуждения
> от 2026-09-23. Решения здесь — направление, а не принятый дизайн; перед
> реализацией каждого пункта нужен отдельный проход обсуждения (см. раздел E в
> [todo.md](../todo.md)).

## Проблема

Текущие интерфейсы (MCP, `/api`, веб-CRUD) механические: пользователь вручную
создаёт каждую сущность и каждую связь между ними. Целевая картина — система
сама поддерживает связность данных, а пользователь занимается исследованием:
читает источники и вносит то, что в них нашёл. CRUD-страницы не выбрасываются —
остаются основой и постепенно обрастают помощниками.

## Принципы

1. **Пользователь работает с источником, сущности — побочный продукт.**
   Центральная точка ввода — фрагмент источника (`Citation`) или
   структурированная запись документа ([records.md](records.md)); персоны,
   места, события и связи возникают из них.
2. **Система ничего не создаёт молча.** Автоматика либо предзаполняет поля
   (видимо, с пометкой происхождения и снятием одним кликом), либо создаёт
   *предложения*, которые человек принимает или отклоняет, в том числе пакетом.
3. **Персоны не связываются автоматически.** Установление личности
   («этот Иван Петров — тот же, что в ревизской сказке?») — решение человека;
   система только показывает кандидатов и доводы. Топонимы и словарные значения
   при высокой уверенности предзаполнять можно.
4. **Доказательство — бесплатно.** Всё, что создано из записи или фрагмента,
   автоматически получает `SourceLink` на соответствующую `Citation`.
5. **Без внешних LLM.** Все сценарии (извлечение, разбор, подсказки)
   реализуются внутри сервиса. Пользователь может подключить своего агента через
   существующий MCP (отчёты, анализ), но система от этого не зависит.
6. **Обратимость.** Всё, что создано одним действием, помечено пакетом изменений
   и происхождением (`origin`) и может быть отменено целиком
   ([assisted-entry.md](assisted-entry.md#журнал-пакетов-изменений-и-отмена)).

## Конвейер

```
источник → ввод (форма записи / текст фрагмента)
        → поиск упоминаний и сопоставление с базой (контекст + тип записи как подсказка)
        → предложения (сущности, связи, факты)
        → подтверждение человеком
        → сущности и связи с SourceLink → разметка текста и обратные ссылки
```

## Зависимости от текущих работ

Сейчас API и UI есть только у административного деления. Люди, события,
источники и архивы — следующие вертикальные срезы (раздел C в
[todo.md](../todo.md)). Их контракты стоит проектировать с учётом этого раздела:
составные сценарии, `origin`/пакет изменений, поле аннотаций в DTO — иначе
переделка.
